<h3>What went well</h3>
We planned adequately for each feature, and user stories were appropriately assessed for the first half, allowing for easy division of work and a continuous, parallel work environment. Additionally, pair programming was made easy with this division of tasks, as we were each able to discuss and inform the other during implementation of each feature.

<h3>What was difficult</h3>
We did not prepare to implement testing in the first half and were pressed for time before the first mid-project deadline. Additionally, certain features such as the interaction between the filter and ingredient usage required refactoring in the second half due to unexpected functionality when new features were added that interacted with old features.

<h3>What the pair would improve next time</h3>
We would implement testing more prominently in our planning and prepare more time during each phase of the project to account for the amount of testing. Additionally, we would start each feature by writing tests because writing them after implementation felt more like confirming what we wrote rather than confirming correct functionality. This would result in a less front-loaded experience overall.

<h3>Whether the final app met the original goal</h3>
Yes, based on our outline of a completed application and individual stories, all aspects of the project were completed within the original planning scope. More testing could be done, however, to ensure correct functionality in all cases as appropriate.
